## DWARF数据是如何生成的

### 为什么要看生成过程

前面 7.1–7.7 我们把程序从源码送到了进程：构建、ELF、符号表、重定位、加载、地址换算，也用标准库把 ELF 和符号表读了出来。接下来自然要问：调试信息是谁、在什么时候、按照什么规则写进二进制的？

这一节会涉及一些 DWARF 术语，比如 DIE、Tag、Attribute、行号表、CFI。第8章会系统解释这些概念；如果你现在还不熟，第一遍先抓“编译器产出符号、链接器合并输出”的主干，不要被代码细节卡住。

答案的一半在编译器，一半在链接器：

- `go tool compile` 在编译每个包时，把类型、变量、函数、行号表等信息编码成一系列 `SDWARF*` 符号，暂时存放在目标文件里；
- `go tool link` 把所有目标文件里的这些符号收集起来，合并编译单元、解析跨单元引用、分配地址、生成 `.debug_line`/`.debug_frame` 等 section，最后按需压缩，写入可执行文件。

理解这条流水线，至少有三个好处：

1. 调试器读不到某个变量的 DWARF 信息时，你能判断是编译器没生成、链接器合并时丢了，还是调试器自己没读对；
2. 你需要写测试程序验证某个语言特性的 DWARF 表示时，知道该看编译器的哪个阶段、链接器的哪个阶段；
3. 你想给 Go 工具链提 bug、或者扩展对 Go 新特性的支持时，知道从哪里下手。

### 本节安排

- **7.8.1 如何跟踪 DWARF 生成过程**：走读代码、调试跟踪、eBPF 跟踪等几种办法，以及怎么构建一个带 DWARF 的 Go 工具链。这一节是方法论，第一遍可以跳过。
- **7.8.2 编译器生成 DWARF 数据**：跟着 `gc.Main()` 看 `dwarfgen.RecordFlags()`、`RecordPackageName()`、`dumpGlobal()`、`populateDWARF()` 等关键步骤。
- **7.8.3 链接器生成 DWARF 数据**：跟着 `ld.Main()` 看 `dwarfGenerateDebugInfo()`、`dwarfGenerateDebugSyms()`、`dwarfcompress()` 的分工。

### 阅读提示

这一节是“知其所以然”的深潜，不是写出断点、变量查看、栈回溯的前提。第一遍读不懂没关系，先把“编译器生成 `SDWARF*` 符号、链接器合并成 `.debug_*`”这个总图记住，等第9章遇到具体的 DWARF 数据对不上时，再回来查对应的小节。

> 本节涉及的编译器、链接器源码以 go1.24 为基线。Go 1.25 起默认生成 DWARF v5，生成流程和 section 组织有一些变化，但“编译器产出符号、链接器合并输出”的主干没有变。版本差异见附录 12.6。
