# Terms

本书内容涉及编译器、链接器、操作系统、调试器、调试信息标准以及软件开发等多个领域，会用到大量的专业术语。为了方便读者查阅，这里集中列出常见且重要的术语及其含义。

| **Term**             | **Description**                                                                                                                                                                                                                                                                                                                                                        |
| :------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source                     | 源代码，指开发者使用编程语言编写的程序文本，例如使用 Go 语言编写的源代码                                                                                                                                                                                                                                                                                                     |
| Compiler                   | 编译器，负责将源代码编译成目标文件的程序，通常会依次完成词法分析、语法分析、语义分析和代码优化等阶段                                                                                                                                                                                                                                                                         |
| Linker                     | 链接器，负责将编译器生成的目标文件与共享库、系统启动代码等链接到一起，最终构建出可执行程序                                                                                                                                                                                                                                                                                   |
| Debugger                   | 调试器，用于跟踪正在运行的进程，或者装载 core 文件，以查看、修改和控制进程的运行时状态，例如暂停执行、查看内存与寄存器，或者分析 core 文件中的堆栈信息。从架构上看，调试器一般可以分为**前端**和**后端**两部分                                                                                                                                                   |
| Debugger Frontend          | 调试器前端，主要负责与用户进行交互：接收用户输入的调试命令，并以友好的方式将执行结果展示给用户。前端可以是命令行界面（CLI）、图形界面（GUI）或集成开发环境（IDE）插件等。前端本身不直接与被调试进程交互，而是通过后端完成具体的调试操作                                                                                                                                      |
| Debugger Backend           | 调试器后端，负责与被调试进程（tracee）进行实际的交互，包括进程控制、断点设置、内存与寄存器读写、符号信息加载等。后端通常以服务的形式运行，接收前端发来的调试命令请求，并将执行结果返回给前端。前后端之间可以通过 RPC 进行远程通信，从而实现分布式或跨平台调试                                                                                                                |
| DWARF                      | DWARF 是一种调试信息标准，规定了编译器、链接器生成调试信息时应遵循的格式。编译器、链接器按照该标准，将类型、变量、函数、源码行号等调试信息写入目标文件和可执行文件中；调试器则负责加载并解析这些调试信息，将机器码与源代码对应起来。简言之，DWARF 是编译器、链接器和调试器之间共同遵循的约定，也是**符号级调试得以实现的基础**                                         |
| Debugger types             | 调试器类型。根据是否依赖调试符号信息，调试器通常可以分为两种类型：**指令级调试器**和**符号级调试器**                                                                                                                                                                                                                                                             |
| Instruction level debugger | 指令级调试器，主要面向指令级别的执行控制，例如设置指令地址断点、运行到断点或执行单步操作等。在查看进程内存和寄存器数据时，它提供相对低级的操作，例如查看内存数据时需要指定以二进制或十进制格式显示。指令级调试器不依赖调试符号信息，因此不支持基于源代码符号进行程序控制和数据操作。指令级调试器在逆向工程等安全分析领域也很常见                                             |
| Symbol level debugger      | 符号级调试器，通常具备指令级调试器的全部功能，同时依靠可执行程序中的调试符号信息，建立内存地址、指令地址与源代码之间的映射关系。它支持在源代码位置设置断点、使用源代码符号查看和修改变量、通过源代码表达式设置断点条件，还可以查看当前调用堆栈。符号级调试器具备许多指令级调试器所没有的高级功能，使得使用高级语言开发时的软件调试变得十分便利                               |
| Tracee                     | 泛指被调试的进程。准确地讲，tracee 指的是被调试器跟踪的**线程**：一个被调试器调试的进程可能是多线程程序，如果需要对其中多个线程进行调试跟踪，那么就会存在多个 tracee                                                                                                                                                                                                   |
| Tracer                     | 泛指调试器对应的进程，严格来讲也是线程。以 Linux 为例，tracer 指的是通过 ptrace 系统调用的 PTRACE_ATTACH/PTRACE_SEIZE 与 tracee 建立跟踪、被跟踪关系的调试器中的线程。Linux 内核要求 ptrace attach/seize 之后的后续 ptrace 请求必须来自发起该 attach/seize 请求的线程，因此 Linux 下的调试器实现往往会有一个专门的线程作为 tracer，负责与被调试进程中的多个 tracee 进行交互 |
