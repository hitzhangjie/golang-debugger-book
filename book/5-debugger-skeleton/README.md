## 走进调试器开发

从本章开始，我们正式走进调试器开发的世界。

本章内容分为七个部分：

- **需求分析**：从功能性需求和非功能性需求两个维度，分析现代调试器应该具备的核心能力
- **架构设计**：介绍调试器的分层架构设计，以及前后端分离式架构如何支撑多样化的调试场景
- **命令管理**：介绍如何借助 spf13/cobra 管理调试器命令，并实现命令的分组展示
- **输入自动补全**：介绍调试器启动命令及调试会话命令的输入自动补全方案
- **可扩展性设计**：补充插件机制、脚本化与自动化、可配置性、多客户端接入等架构之外的扩展性维度
- **实施方案**：确定具体的实现策略，并说明配套示例工程 godbgv2 的组织方式——一个小节一个提交、一个 tag，从调试器骨架到指令级、符号级调试器逐章节演进
- **功能演示**：通过实际运行效果，展示调试器的各项功能和交互体验

在本章中，我们将从需求分析切入，探讨开发一个调试器时需要关注的核心要点，随后逐步梳理调试器的技术架构，确定具体的实施方案，最终实现一个能够运行的调试器雏形。

在此基础上，我们还将继续深入，逐步实现指令级调试、符号级调试，带领读者一步步理解调试器的工作原理与设计实现。

> tip: 本章结束后，读者也将掌握使用 [spf13/cobra](https://github.com/spf13/cobra) 进行命令行程序开发的一些技巧，比如命令管理、选项管理、参数管理、help 信息管理，以及如何实现自动补全等等。Go 语言经常被用来开发各种实用的命令行工具，而 spf13/cobra 正是当前命令行开发领域最成功的项目之一，很多知名项目的命令行工具都是基于它构建的，比如 kubernetes、hugo、GitHub CLI 等等。
