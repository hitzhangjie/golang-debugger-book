## 高级功能扩展

在前面的章节中，我们详细介绍了调试器的核心功能设计与实现，包括进程控制、断点管理、调用栈分析等基础特性。这些功能构成了调试器的核心框架。本节讨论的是另一类内容：高级扩展功能。它们不是调试器能用的前提，但直接影响它好不好用、能不能长期维护。

需要先交代一个前提：**本节讨论的 12 个方向，godbgv2 基本都没有实现**。其中 starlark、eBPF-based tracing、rr 反向调试是既定的范围决策（🚫 有意不做，见 9.2.00 的 ps 段），其余是尚未规划的空白（❌ 缺失）。所以本节的定位是**扩展阅读**：设计思路可以迁移借鉴，代码不并入 godbgv2。

### 12 节导览

- **9.3.100 starlark**：语言特点 → 在 Go 程序里嵌 REPL → delve 的 `dlv_command`/`cur_scope` 绑定 → `debug.star` 自动化调试；示例与实现都属于 delve。
- **9.3.101 eBPF 跟踪**：breakpoint-based 与 eBPF-based 的取舍、eBPF 程序的加载与数据回收，以及 Go GMP 调度下按 goid 归并 uprobe 事件的难点。
- **9.3.102 语法高亮**：用 `go/ast` 做 colorize，把关键字、标识符、注释等 token 映射到终端颜色；代码出自 delve，书中附了修复，属于扩展阅读。
- **9.3.103 分页输出**：`pagingWriter` 的三种输出模式（终端 / 分页器 / 文件），以及「输出多长才转分页」的判断。
- **9.3.104 分离 DWARF**：为什么发行版要把调试信息剥出去，`.gnu_debuglink`、`.dwp` 的命名与查找约定，以及调试信息目录的搜索顺序。
- **9.3.105 路径映射**：客户端与目标机源码路径不一致的两类问题，delve 的 `substitutePath` 如何按模块路径统计出映射。
- **9.3.106 目标进程 IO 重定向**：`--tty` 与重定向到文件/管道两种思路，解决交互式程序与调试器 REPL 抢同一个终端的问题。
- **9.3.107 配置系统**：配置文件的位置与分层、`cmds.Merge` 的合并方式，以及 `config` 命令的几种用法。
- **9.3.108 多客户端**：`--accept-multiclient` 的由来，单客户端与多客户端模式下连接生命周期和退出语义的差异。
- **9.3.109 transcript**：把会话输出同时写到文件，`-t`/`-x`/`-off` 的语义，以及它与 `--init` 回放的方向差异。
- **9.3.110 确定性调试**：record & replay 要解决什么问题，mozilla rr 的设计原理、技术约束与性能数据。
- **9.3.111 冒烟测试机制**：脚本 DSL（`@exec`/`@capture`/`=` 断言）与 `make smoke S=ch9.2.40` 的驱动方式；机制本身已在 6.5 与 `godbgv2/docs/SMOKE-HARNESS.md`，本节讲上量到符号级命令之后的取舍。

### 阅读约定

1. 本书自研项目统一称 **godbgv2**（二进制名 `godbg`）。**tinydbg** 是第 9 章早期基于 delve 裁剪的参考实现，只作历史对照出现——它出现过的地方，不代表 godbgv2 有对应能力。
2. 本节的代码片段分两类：能在 godbgv2 里用 `git show <tag>:<path>` 复核的，和设计示意 / 第三方实现（delve、rr）。后者一律标注出处，不作为本书实现。
3. 涉及第三方代码（如 100 的 starlark 绑定、102 的 colorize）只讲做法与出处，不搬进 godbgv2。
4. 每节开头的状态横幅与 `FEATURE-MATRIX` 的记号严格一致；本节 12 个方向只用到 ✅/🚫/❌，没有计划内的桩，因此不出现 🅿️。
